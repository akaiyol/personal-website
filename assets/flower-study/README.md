# Procedural flower field

`field.js` owns growth, independent sway, input and visibility. `bloom-renderer.js` supplies the authored ribbon geometry, numeric cups, seeded dot coefficients and Canvas fallback. `bloom-gpu.js` deforms those same seeded dots in a worker WebGL context, with stencil masks for petal overlap and a cached numeric glyph atlas.

The worker returns one atlas containing every bloom at the requested growth stages. This replaces serial per-flower bitmap transfers, which left too few actual opening shapes during the 3.8-second entrance. A persistent framebuffer retains completed tiles; each batch rasterizes only changed blooms. One batch runs at a time, and the next uses current growth rather than queuing old animation/input events. Texture coefficients are prepared once per plant/layout. Atlas tiles retain the authored geometry at two pixels per design unit.

Resize generations discard obsolete results and replaced bitmaps are closed. Hidden/offscreen fields dispatch no further batches; a batch already running may finish. Unavailable or lost worker WebGL uses the shared Canvas renderer in the worker. Unsupported or failed workers use that renderer on the main thread. Each leaf texture is cached per plant/layout. Recovery preserves the artwork and interactions; its speed remains hardware-dependent.

No external textures or libraries are fetched. `.assetsignore` explicitly includes the field and all three bloom scripts. `index.html` loads the shared renderer before the field.

Verification: run the project `flowerIntro` and `work` recipes for input/lifecycle, then `scripts/verify-flower-rendering.cjs BASE_URL EVIDENCE_DIRECTORY` against an owned canonical public preview. Pixel parity covers full, partial and empty growth at 1280/390/320px with GPU workers, Canvas workers, unavailable workers and deliberate worker load failure. It checks resize, rewind clearing and reduced-motion completion.

Run `scripts/verify-bloom-cadence.cjs BASE_URL EVIDENCE_DIRECTORY` separately from other browser tests. It counts distinct growth stages actually painted from worker bitmaps during the opening interval, rather than counting requestAnimationFrame callbacks or desired stages. Its desktop regression budget requires at least 18 opening shapes per flower and no gap above 85 ms on the verification machine. The preceding release produced as few as 10; the corrected GPU batch path produced at least 22 in the same Chromium environment. These are controlled local observations, not a frame-rate guarantee on visitor hardware. Physical Safari, device-specific GPU behavior and real-user outcomes need separate evidence. Use the rendered critique for visual and motion assessments.
